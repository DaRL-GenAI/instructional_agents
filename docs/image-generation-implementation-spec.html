Dynamic image generation for the HTML slides workflow

Port the gpt-image-2 dynamic image pipeline from the agentic frontend-slides skill into the ADDIE workflow: the presentation-design deliberation decides whether and how images fit the course, and the Teaching Assistant agent scouts, prompts, generates, and injects images into the HTML deck — leaving slides.tex and the Beamer PDF untouched.

context

Overview & invariants

The better-slides-generation branch already converts each chapter's TA-authored Beamer slides.tex into a self-contained offline HTML deck (chapter_N/html/slides.html) plus screenshot-based slides-html.pdf / slides-html.pptx exports. The reference implementation at ~/Developer/sandbox/new-frontend-slides-skill (package agentic_frontend_slides, file image_pipeline.py) adds AI-generated figures behind a --dynamic-img-gen flag. This spec ports that capability.

Head start

The consumer side already exists, unused, in src/html_slides.py: ContentElement.image_data_uri (~line 68), element_weight() weight 4 for generated_image/user_image (~1067), render_element() emitting <figure class="gen-image-card"><img src="{image_data_uri}" alt="{title}"> (~2193), and the .gen-image-card img CSS (~1445, max-height 460px, themed border/shadow). Nothing constructs those elements today — only the producer side is missing.

Invariants — do not break

  • slides.tex and slides.pdf stay byte-identical. Images exist only in the HTML deck and its exports (which screenshot the HTML, so they pick images up for free).
  • Best-effort everywhere. No stage of the image pipeline may ever abort a chapter build — every failure degrades to a warning, matching the reference implementation.
  • Backward compatible. Existing course_slide_style.json files (no image_guidance block) must load with images disabled — no schema-version bump, no forced --reselect-presentation-design. Existing 2-positional-argument calls to finalize_chapter(course_dir, chapter_dir) must keep working.
  • Two gates for any spend. The persisted experiment opt-in (course_image_generation.json, default disabled) and the deliberation's verdict (style.image_guidance.enabled) must both be on. Capped mode takes the strictest configured budget; AI-decides mode removes the numeric chapter cap.
  • Alt text comes from element.title, not element.text — set title=concept when constructing the element.
  • Title slides never render elements. choose_layout() early-returns for slide.is_titlepage, so an image placed there would silently vanish — exclude title slides in code, not just in prompts.

src/html_slides_style.py

Deliberation extension — image guidance

New schema

Add near the other dataclasses; image_guidance becomes the last field of CourseSlideStyle.

@dataclass(frozen=True)
class ImageGuidance:
    enabled: bool
    visual_types: list[str]        # subset of IMAGE_VISUAL_TYPES
    prompt_style_notes: str        # <=1200 chars — palette/mood/subject guidance for prompt writing
    avoid_notes: str               # <=600 chars — universal + course-specific "never depict" rules
    max_images_per_chapter: int | None # 0–3, or None when AI decides

IMAGE_VISUAL_TYPES = {
    "conceptual-diagram", "process-flow", "architecture-overview",
    "data-metaphor", "comparison-illustration", "scene-illustration",
    "abstract-motif", "icon-composition",
}

DEFAULT_IMAGE_GUIDANCE = ImageGuidance(
    enabled=False, visual_types=[], prompt_style_notes="",
    avoid_notes="", max_images_per_chapter=0,
)

IMAGE_SAFETY_GUIDANCE = (
    "Generated images must never include embedded text, letters, numbers, "
    "labels, logos, watermarks, UI chrome, or real identifiable people."
)

Where the decision is made

  • Group deliberation: extend the summarizer contract with a separately validated image_recommendation. Reviewers decide whether imagery helps this course and which types fit. In capped mode they also choose a per-chapter budget; in AI-decides mode they return a null budget.
  • Preserve existing style validation: extract the image recommendation, then pass the remaining payload through the established selection canonicalizer and validator.
  • Materializer: consume the validated recommendation plus course/chapter/catalog context and emit operational image_guidance. It may refine prompt notes but may not reverse the deliberation's enabled verdict.

Validator rules — _validate_image_guidance(raw)

  • enabled must be a boolean; visual_types must be a list drawn from IMAGE_VISUAL_TYPES.
  • enabled ⇒ visual_types non-empty; enabled ⇒ prompt_style_notes ≥ 40 chars of course-specific guidance; a numeric enabled cap must be at least 1.
  • max_images_per_chapter is null for AI-decides mode or an int in 0–3 (reject bools — isinstance(x, bool) check before the int check).
  • Disabled normalizes to visual_types=[], max_images_per_chapter=0; strings are bounds-checked (≤1200 / ≤600) and stripped; visual_types deduplicated preserving order.
  • Failures raise FrontendSlidesError and flow through the existing materializer repair-retry loop.

Mandatory safety guidance

Mirror _with_required_guidance(): a new _with_required_image_safety_guidance(style) truncates existing notes to the available space and then appends the mandatory sentence, ensuring it survives the 600-character limit. Call it in both fresh and resume branches.

Backward compatibility

Do not bump the schema version

Keep STYLE_SCHEMA_VERSION = 1. A bump trips the strict version check and forces every existing course through --reselect-presentation-design. Instead, in course_style_from_dict: if data.get("image_guidance") is a dict, coerce it field-by-field with safe defaults; otherwise use DEFAULT_IMAGE_GUIDANCE. Resolve the default before the re-validation call so validate_materialization always receives a well-formed block — legacy files load cleanly with images off (cost-safe), new files always carry a deliberately-reasoned block.

Human-readable output

Extend presentation_design_markdown() with an ## Image Generation Guidance section (enabled, visual types, per-chapter budget, style notes, avoid notes). write_course_style needs no change — asdict() serializes nested dataclasses recursively into course_slide_style.json.

src/html_slides_img.py — new module

The image pipeline — scout → synthesize → prompt → generate

Config and result types

@dataclass(frozen=True)
class ImageGenerationConfig:
    enabled: bool = False
    max_images_per_chapter: int = 3          # capped-mode default
    ai_decides_image_count: bool = False # no numeric chapter cap when true
    model: str = "gpt-image-2"
    size: str = "1536x864"
    quality: str = "medium"
    estimated_cost_per_image_usd: float = 0.06

@dataclass(frozen=True)
class ChapterImageResult:
    attempted: int
    generated: int
    reused_from_cache: bool
    elapsed_time: float
    token_usage: int
    estimated_cost_usd: float
    warnings: list[str]
    slides: list[int]
    images: list[GeneratedImageRecord]

Public entry point

def augment_deck_with_generated_images(
    deck: BeamerDeck, *, chapter_path: Path, style: CourseSlideStyle,
    chapter: dict[str, str] | None, llm: LLM, config: ImageGenerationConfig,
    source_sha256: str, style_sha256: str,
) -> ChapterImageResult:
    """Mutates deck.slides in place. Best-effort: never raises."""

Fast no-op gate at the top: return an empty result when the persisted experiment is disabled, the deliberation vetoes images, or the effective cap is 0. The public boundary catches every exception and returns warnings.

Stage 1 — two scouts in parallel

Two Agents (from src/agents.py, sharing the workflow's LLM instance), role "Teaching Assistant — Visual Opportunity Scout", run via ThreadPoolExecutor(max_workers=2). Each gets the shared guidance with a distinct lens spliced in (ported from the reference skill's workflow_agents.py):

shared scout system prompt (lens interpolated)
"You analyze a parsed slide deck and decide where AI-generated images would genuinely improve the presentation. {lens} Most presentations need FEW or ZERO generated images. If the deck communicates well without images, return {"suggestions": []} — an empty list is a correct, complete answer. There is no minimum or maximum count. Never suggest an image for the title slide, for slides that are mostly code, tables, or equations, or where an image would merely decorate."
lens A — pedagogy
"You look through a CONCEPTUAL-DIAGRAM and PEDAGOGY lens: find slides where an abstract concept, process, relationship, or structure would be easier to grasp with a single clear illustrative figure."
lens B — engagement
"You look through an AUDIENCE-ENGAGEMENT and VISUAL-METAPHOR lens: find slides where a striking but relevant visual metaphor or scene would make a dry or text-heavy moment memorable without distorting the content."

Scout input: chapter title/description, image guidance, and a bounded semantic outline containing each slide's title, element-weight summary, and a sanitized 300–500 character content excerpt. Output includes visual_type and optional native-HTML labels.

Stage 2 — synthesis

referee system prompt
"You are the final referee for image placement in a slide deck. Merge the two scout lists. Keep at most one image per slide_index. Drop any suggestion that is weak, duplicative, or decorative — only keep images that genuinely improve the slide. You may return an empty placements list ({"placements": []}) if no suggestion is strong enough."

One "Teaching Assistant — Image Placement Referee" call; output {"placements": [...]}, deduplicated again by slide_index in code (keep first).

Code-enforced validation — never trust the model

  • Reject slide_index values that are out of range, duplicated, or point at a slide.is_titlepage slide.
  • Reject slides where code, table, or equation content dominates total element weight; a small technical element is not disqualifying.
  • Reject visual_type values outside style.image_guidance.visual_types; require non-empty single-sentence rationale/image_concept under 500 chars.
  • Truncate the surviving list to the effective cap (this enforces the budget — truncation, not failure).
  • All JSON calls use the repair-retry pattern from html_slides_style.py: feed validation errors and the truncated previous response back, at most 2 retries; persistent failure → empty result plus warnings, deck untouched.

Stage 3 — batched prompt writer

prompt-writer system prompt
"You write image-generation prompts for presentation figures. Every prompt must match the deck's visual style, describe a wide 16:9 landscape composition with generous negative space, and must forbid any text, letters, numbers, labels, watermarks, or logos in the image."

One "Teaching Assistant — Image Prompt Writer" call covering all placements (not one call per image). Output: {"prompts": [{"slide_index", "prompt"}]} with exactly one prompt per expected index, each 1–1500 chars, specifying composition, subject, style, and palette in concrete visual terms. Inject as user content: the selected style name, a ta_guidance excerpt, render_theme accent/background/text colors, and image_guidance.prompt_style_notes / avoid_notes.

Deterministic fallback if the call fails or indexes mismatch after retries (verbatim from the reference):

def _fallback_prompt(concept: str, accent: str, background: str) -> str:
    return (
        f"Clean minimal presentation figure illustrating: {concept}. "
        f"Wide 16:9 landscape composition, flat modern illustration, palette accents "
        f"{accent} on {background}, generous negative space, absolutely no words, "
        "letters, labels, or watermarks."
    )

Stage 4 — generation loop

Sequential (no async infra exists in this codebase; budgets are ≤3 and wall-clock is dominated by LaTeX + Playwright anyway). Per-image failure → warning, continue.

images_dir = chapter_path / "html" / "images"
for placement in placements:
    try:
        response = llm.client.images.generate(
            model=config.model, prompt=placement.prompt,
            size=config.size, quality=config.quality,
        )
        b64 = response.data[0].b64_json          # default return format for gpt-image-2
        png_bytes = base64.b64decode(b64)
    except Exception as exc:
        warnings.append(f"slide {placement.slide_index}: image generation failed: {exc}")
        continue
    digest = hashlib.sha256(placement.prompt.encode("utf-8")).hexdigest()[:16]
    images_dir.mkdir(parents=True, exist_ok=True)
    (images_dir / f"img-{placement.slide_index:02d}-{digest}.png").write_bytes(png_bytes)
    deck.slides[placement.slide_index - 1].elements.append(
        ContentElement(
            kind="generated_image",
            title=placement.concept[:200],       # becomes the alt text in render_element()
            image_data_uri=f"data:image/png;base64,{b64}",
        )
    )

The on-disk PNG is the audit/cache copy; the HTML embeds the base64 data URI so slides.html stays fully self-contained and offline.

Caching & idempotency

chapter_N/html/images/image-manifest.json

{
  "schema_version": 1,
  "source_sha256": "<slides.tex hash>",
  "style_sha256": "<course_slide_style.json hash>",
  "enabled": true,
  "placements": [
    { "slide_index": 4, "concept": "...", "prompt_sha256": "...", "file": "img-04-….png" }
  ],
  "elapsed_time": 8.2, "token_usage": 1450, "estimated_cost_usd": 0.06
}

Cache identity covers source, style, chapter context, effective cap, model, size, quality, and a pipeline prompt version. Normal reruns reuse matching assets with zero calls. --replace-images ignores the cache and stages a new set; it commits only after all planned images and HTML/export validation succeed. Failure keeps the prior set, while a valid empty placement result intentionally clears it.

Hook into finalize_chapter

New parameters are keyword-only with defaults so the existing 2-positional-arg call sites (ADDIE.py:~492 and local_course_cli/cli.py's refinalize_existing_chapters) keep working unchanged:

def finalize_chapter(

The early-return check first compares requested image state with manifest metadata, so new enablement and replacement cannot be skipped. Augmentation then runs after speaker-note correlation and before rendering.

image_result = augment_deck_with_generated_images(

html_stale = html_stale or not image_state_current or image_config.replace_images

The augmentation boundary is always invoked, but returns immediately without agent or image calls when either gate is off. It reads and mutates only the parsed frontend deck. Rendering and export use staged files; image manifests and assets commit only after validation succeeds.

economics

Cost & statistics

Per enabled uncached chapter: 2–4 LLM calls (two scouts, then synthesis and prompt writing only when needed) plus image generations for the selected placements. Capped mode allows 0–3; AI-decides mode may select any number up to the eligible slide count. The configured estimate is $0.06 each (gpt-image-2, 1536×864, medium). Each invocation appends timestamped incremental statistics; cache hits report zero new spend.

  • chapter_N/statistics_slide_images.json — attempted, generated, reused_from_cache, elapsed_time, token_usage, estimated_cost_usd, warnings.
  • chapter_N/frontend-slides-manifest.json — new "images" sub-object for quick inspection.
  • Course statistics.json — one appended slide_images_chapter_N entry per chapter (existing merge pattern).
  • statistics_slide_style.json — no change needed; the materializer's slightly larger prompt is counted naturally.
